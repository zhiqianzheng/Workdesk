按当前使用的 Agent WeChat v2.2.0 原生后台说明

先认清这四个角色

好友的微信发消息、看回复
⇄
腾讯微信服务器接收与投递微信消息
⇄
你的电脑
Agent WeChat登录微信 · 收发消息 · 保存记录
⇅
Workdesk检查接管范围 · 整理上下文 · 调用 AI
⇄
你配置的 AI 服务根据提交的对话生成回复

AI 服务与 Workdesk 通信；微信服务器与 Agent WeChat 通信。AI 服务不直接登录你的微信。

跟着一条消息走一遍

展开 Agent WeChat：内部主要做六件事

01 / 登录与授权

确认“以谁的身份通信”

通过手机扫码确认或可用的已保存设备授权登录。保存登录状态，并进行验证和续期；授权失效时可能需要再次确认。

02 / 协议通信

把操作变成网络请求

自行实现微信协议通信，组织请求、进行加密传输、解析响应。原生后台不加载或启动官方微信程序，也不依赖鼠标点击窗口。

03 / 同步任务

检查有没有新消息

为账号运行同步任务：源码包含长连接通知触发同步，连接不可用时退回心跳轮询。保存“同步进度”，像书签一样记住上次同步到哪里。

04 / 本地存储

把可用记录留在电脑上

保存消息、联系人及同步状态，为查看历史、总结提供数据。仅限本机已有或已同步的数据，不能据此获取手机上的全部历史。

05 / 本机接口

让 Workdesk 调用

通过 127.0.0.1:6175 提供本机 HTTP 接口，并验证本机令牌。Workdesk 经此读取消息、获取新消息事件和提交发送任务。

06 / 发送与结果记录

真正执行微信发送

接收发送任务，提交给微信服务器并记录结果。幂等标识减少同一任务重复提交；结果未知时盲目重发仍可能造成重复。

关键区别：Workdesk 决定“要不要回、怎么回”；AI 服务生成内容；Agent WeChat 执行微信通信。服务器接受消息，也不等于好友已经阅读。

三个“钥匙”，各管一段连接

微信登录授权

Agent WeChat ⇄ 腾讯服务器

证明微信账号和设备身份。登录态属于敏感数据。
本机接口令牌

Workdesk ⇄ Agent WeChat

限制谁可以调用本机后台，不是微信登录凭据。
AI API Key

Workdesk ⇄ AI 服务

调用你配置的模型服务，不能用来登录微信。

你可能最关心的几个问题

它是不是在偷偷操作我打开的微信窗口？

当前原生后台独立运行，不加载或启动官方微信可执行程序。它实现协议通信和本地数据读写。如果使用接管官方数据目录的模式，上游要求官方客户端保持关闭，避免同时写入同一份数据。

协议通信到底是什么？

就像双方约定好的通信语言：请求需要包含什么字段、怎样编码和加密、如何验证账号、怎样解释服务器返回的数据。Agent WeChat 自己实现这套通信逻辑。文档列出 MMTLS / Hybrid 传输等能力；这不表示它得到了腾讯官方个人机器人接口授权。

为什么有时消息不能立刻收到？

v2.2.0 源码包含长连接通知及轮询回退；上游文档仍将真实账号主动推送列为未验证，不能据此确认当前账号正在使用推送。正常轮询间隔为 5–30 秒，工作线程出错时退避可到 60 秒。这不是消息到达时限，网络与登录状态也会影响延迟。

AI 能看到哪些聊天？

模型看到的是 Workdesk 本次提交的上下文和风格信息，不会仅凭 AI API Key 自动读取微信。微信同步数据先落在本机，随后由 Workdesk 选择内容提交给你配置的服务。提交出去的聊天内容涉及隐私。

发送图片和发送文字有什么不同？

文字发送主要提交接收人和文字内容。图片通常还要准备并上传媒体资源，再发送引用该资源的消息。AI 生成图片成功，并不代表图片已成功发送到微信。

这种方式会不会触发微信风控？

不能保证不会。它属于非官方客户端协议通信，能成功运行不等于得到官方许可。协议或服务端策略变化可能导致登录、同步、发送失败或账号限制。只监听本机接口能减少接口暴露，但不能消除微信侧风险。AI 数据隐私则是另一条需要单独考虑的链路。
